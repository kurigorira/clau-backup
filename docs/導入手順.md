# 導入手順

対象：Apache24 / PHP / MySQL / SQLite が動いている院内のWindowsサーバー（インターネット接続なし）
所要時間：1〜2時間程度

---

## 0. 事前に用意するもの（院外で準備して、院内のルールに沿って持ち込む）

| もの | 入手先・備考 |
|---|---|
| このリポジトリの `backup\` フォルダ一式 | ZIPにして持ち込む |
| `sqlite3.exe` | https://sqlite.org/download.html の「sqlite-tools-win-x64-*.zip」。中の `sqlite3.exe` だけ使う |
| NASの共有フォルダと専用アカウント | NASの管理者に依頼する（例：`\\NAS01\backup\webserver`、ユーザー `svc_backup`） |

> `mysqldump.exe` / `mysql.exe` は、MySQLをインストールしたフォルダの `bin` にすでにあります。

## 1. フォルダを作る

管理者の PowerShell で実行します。

```powershell
New-Item -ItemType Directory C:\backup\scripts, C:\backup\tools, C:\backup\secure, C:\backup\logs, C:\backup\work -Force
# backup\ の中身を C:\backup\scripts\ にコピー
# sqlite3.exe を C:\backup\tools\ にコピー
```

`C:\backup\secure` は Administrators とバックアップ実行アカウントだけが読めるようにします。

```powershell
icacls C:\backup\secure /inheritance:r /grant:r "Administrators:(OI)(CI)F" "SYSTEM:(OI)(CI)F" "svc_backup:(OI)(CI)R"
```

## 2. Windowsにバックアップ実行用のアカウントを作る

NASの専用アカウントと**同じユーザー名・パスワード**でローカルユーザーを作ると、NASへの接続設定が不要になります（ワークグループ環境の場合）。

```powershell
$pw = Read-Host -AsSecureString 'svc_backup のパスワード'
New-LocalUser -Name svc_backup -Password $pw -PasswordNeverExpires -Description 'NASバックアップ実行用'
Add-LocalGroupMember -Group Administrators -Member svc_backup
```

ドメイン環境なら、ドメインのサービスアカウントを使ってください。
NASに接続できるか確認します：`runas /user:svc_backup "cmd /c dir \\NAS01\backup\webserver"`

## 3. MySQLにバックアップ用アカウントを作る

MySQLにrootでログインして、次を実行します（読み取り権限だけなので、このアカウントでデータが書き換わることはありません）。

```sql
CREATE USER 'backup'@'localhost' IDENTIFIED BY '長いパスワード';
GRANT SELECT, SHOW VIEW, TRIGGER, LOCK TABLES, EVENT, PROCESS, RELOAD ON *.* TO 'backup'@'localhost';
-- MySQL 8.0.20以降は次も実行する（MariaDBでは不要）
GRANT SHOW_ROUTINE ON *.* TO 'backup'@'localhost';
```

`backup\mysql-backup.cnf.sample` を `C:\backup\secure\mysql-backup.cnf` としてコピーし、パスワードを書き換えます。

## 4. 設定ファイルを書き換える

`C:\backup\scripts\config.ps1` をメモ帳で開き、**（仮）** と書いてある箇所を実際の環境に合わせます。

- `NasRoot`：NASの共有パス
- `MySqlBinDir`：`mysqldump.exe` があるフォルダ（例：`C:\Program Files\MySQL\MySQL Server 8.0\bin`）
- `Items`：`php.ini`・`my.ini` の場所と、その他の重要フォルダ
- `SqliteFiles`：htdocsの外にあるSQLiteファイルがあれば追加する（htdocsの下は自動で探します）

> 保存するときは文字コードを **UTF-8（BOM付き）** にしてください（Windows PowerShell 5.1 で日本語が文字化けしないように）。メモ帳なら「名前を付けて保存」→ 文字コード「UTF-8 (BOM 付き)」。

## 5. 手動で1回実行してみる

```powershell
cd C:\backup\scripts
powershell -NoProfile -ExecutionPolicy Bypass -File .\backup.ps1
```

確認すること：
- 最後に「バックアップ成功」と表示される
- NASに `daily\yyyyMMdd_HHmmss\` ができていて、`mysql\`・`sqlite\`・`files\`・`manifest.json` がある
- 「SQLite バックアップ: ...」に、想定しているSQLiteファイルがすべて出ている

## 6. 試し復元をしてみる（必須）

```powershell
.\restore.ps1 -List
.\restore.ps1 -Target MySql -Database <DB名> -AsDatabase <DB名>_restoretest
.\restore.ps1 -Target All          # C:\restore\<日時>\ にファイルとSQLiteを取り出す（元の場所は変更しない）
```

別名のDBの件数を元のDBと比べ、問題なければ削除します：`DROP DATABASE <DB名>_restoretest;`

## 7. タスクスケジューラに登録する

```powershell
.\register-task.ps1 -RunAsUser "$env:COMPUTERNAME\svc_backup"
Start-ScheduledTask -TaskName 'WebServer Daily Backup'   # すぐに試す
```

登録した内容：毎日2:00に実行。サーバーが2:00に止まっていた場合は、起動後にすぐ実行します。4時間を超えたら強制終了します。失敗・警告はイベントビューアーの「Windowsログ → Application」（ソース `WebServerBackup`）にも記録されます。

## 8. NASのスナップショット（ランサムウェア対策）

サーバーがランサムウェアに感染すると、サーバーから書き込めるNAS上のバックアップも暗号化されるおそれがあります。NAS側で、**サーバーからは消せない世代**を持つようにします。

| NASの機種 | 確認する場所 |
|---|---|
| Synology | 「パッケージセンター → Snapshot Replication」→ 共有フォルダごとにスケジュールを設定（毎日4:00、30世代など） |
| QNAP | 「ストレージ＆スナップショット → スナップショット」 |
| Buffalo TeraStation / IO-DATA LANDISK | 機種によって「スナップショット」「レプリケーション」「ごみ箱」機能。取扱説明書で確認する |

スナップショット機能がない場合は、**週1回、外付けHDDに `NasRoot` の最新の日次フォルダをコピーして、ケーブルを抜いて保管する**運用にしてください。

## 9. 毎日・毎月の運用

| いつ | 何をする |
|---|---|
| 毎朝 | サーバーのデスクトップ（またはNAS）に `BACKUP_FAILED_*.txt` / `BACKUP_WARN_*.txt` がないか見る。あれば中を読んで対応し、ファイルを削除する。NASの `LAST_SUCCESS.txt` の日付が昨夜になっていることを確認する |
| 月1回 | 試し復元（手順6）。NASの空き容量の確認 |
| 年1回 | 代わりの担当者が `docs\復元手順書.md` を見ながら試し復元をやってみる |
| 設定を変えたとき | `config.ps1` に対象を追加したら、手動で1回実行して確認する |
