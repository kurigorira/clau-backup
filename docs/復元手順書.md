# 復元手順書（院内Webサーバー）

> **この手順書は印刷して、サーバーの近くに保管してください。**
> 障害時はネットワークやNASにも問題が起きているかもしれないので、画面だけに頼らないようにします。

| 項目 | 値（導入時に書き込む） |
|---|---|
| サーバー名 | |
| NASの共有パス | `\\NAS01\backup\webserver`（仮） |
| スクリプトの場所 | `C:\backup\scripts\` |
| 担当者 / 連絡先 | |
| 代わりの担当者 / 連絡先 | |
| MySQLのrootのパスワードの保管場所 | （例：金庫の封筒） |

---

## まず状況を確認する（5分）

| 症状 | 使う手順 |
|---|---|
| 特定のDBのデータを誤って消した・壊した | **A. DBだけ戻す** |
| htdocsのプログラムを誤って変更・削除した | **B. ファイルだけ戻す** |
| SQLiteのデータがおかしい | **C. SQLiteだけ戻す** |
| サーバーが起動しない、ディスクが壊れた、ランサムウェアに感染した | **D. 新しいサーバーに丸ごと戻す** |

> **ランサムウェアが疑われるとき**は、まずサーバーのLANケーブルを抜いて、情報システム部門・院内の連絡体制に沿って報告してください。感染したサーバーから復元作業をしてはいけません（NASのバックアップまで暗号化されるおそれがあります）。

### どの時点に戻すかを決める

管理者の PowerShell で：

```powershell
cd C:\backup\scripts
.\restore.ps1 -List
```

`名前` 列が日時（`20260925_020000` = 2026年9月25日 2:00:00）です。`状態` が `OK` のものを選びます。
データが消えた・おかしくなった**日時より前**の世代を選んでください。月次（`monthly`）は、毎月最初に成功したバックアップです。

## A. DBだけ戻す（MySQL）

**1. 別の名前で試しに戻して、中身を確認する（元のDBは変更しない）**

```powershell
.\restore.ps1 -Backup 20260925_020000 -Target MySql -Database karte -AsDatabase karte_check
```

MySQL管理者のパスワードを聞かれたら入力します。`karte_check` を開いて、必要なデータがあることを確認します。

> 一部のデータだけ戻したいときは、`karte_check` から必要な行だけを元のDBにコピーする方法もあります（ほかのデータを巻き戻さずに済みます）。

**2. 元のDBを丸ごと戻す**

```powershell
.\restore.ps1 -Backup 20260925_020000 -Target MySql -Database karte -Overwrite
```

`YES` と入力すると実行されます。上書き前のDBは `C:\backup\pre-restore\<日時>\mysql\` に退避されます。

**3. 確認用のDBを削除する**：`DROP DATABASE karte_check;`

## B. ファイルだけ戻す（htdocsなど）

**1. 取り出して中身を確認する（元の場所は変更しない）**

```powershell
.\restore.ps1 -Backup 20260925_020000 -Target Files -Item htdocs
```

`C:\restore\20260925_020000\files\htdocs\` に取り出されます。**1ファイルだけ戻したいとき**は、ここから必要なファイルを手でコピーするのが一番安全です。

**2. フォルダを丸ごとバックアップ時点の状態に戻す**

```powershell
net stop Apache2.4
.\restore.ps1 -Backup 20260925_020000 -Target Files -Item htdocs -Overwrite
net start Apache2.4
```

バックアップ後に追加されたファイルは消えます（上書き前の状態は `C:\backup\pre-restore\<日時>\files\` に退避されます）。`Item` の名前は `config.ps1` の `Items` の `Name`（htdocs / apache-conf / php-ini / mysql-ini など）です。

## C. SQLiteだけ戻す

```powershell
net stop Apache2.4
.\restore.ps1 -Backup 20260925_020000 -Target Sqlite -Overwrite
net start Apache2.4
```

Apacheを止めずに実行すると、PHPが書き込み中のファイルを上書きしてしまうので、必ず止めてから実行してください。取り出して確認するだけなら、`-Overwrite` を付けずに実行します（`C:\restore\<日時>\sqlite\` に出ます）。

## D. 新しいサーバーに丸ごと戻す

1. 新しいサーバーにWindowsを入れ、元のサーバーと**同じバージョン**のApache・PHP・MySQLを、**同じフォルダ**に入れる。
   バージョンは、NASのバックアップフォルダの `manifest.json` の `Versions` に記録されています。
2. MySQLを起動し、rootのパスワードを設定する。
3. `docs\導入手順.md` の手順1〜4を行う（スクリプトの配置、`config.ps1`、`sqlite3.exe`）。
4. Apacheを止めて、すべてを戻す：
   ```powershell
   net stop Apache2.4
   .\restore.ps1 -Backup 20260925_020000 -Target All -Overwrite
   ```
   ファイル → SQLite → MySQL の順に戻ります（htdocsの中のSQLiteは、整合性チェック済みのバックアップで上書きされます）。
5. MySQLのアプリ用アカウントを作り直す：バックアップフォルダの `mysql\_grants.sql` を開き、`<パスワード>` をアプリの設定ファイル（htdocs内の設定ファイル）に書いてあるパスワードに書き換えて、必要な行だけ実行する。
6. `net start Apache2.4` で起動し、ブラウザで画面を確認する。
7. `docs\導入手順.md` の手順7でタスクを登録し直す。

## うまくいかないとき

| 表示 | 原因と対応 |
|---|---|
| `NAS に接続できません` | エクスプローラーで `\\NAS01\...` が開けるか確認する。NASの電源、LAN、アカウントを確認する |
| `ハッシュ不一致` | そのバックアップは壊れています。1つ前の世代を選び直してください |
| `DB 'xxx' は既にあります` | `-AsDatabase` に別の名前を指定するか、元のDBを置き換えるなら `-Overwrite` を付けます |
| `現在のDBの退避に失敗したため中止します` | DBが壊れていてダンプできない状態です。`C:\backup\pre-restore` の空き容量を確認し、それでもだめなら管理者と相談のうえ、MySQLで `DROP DATABASE` してから `-Overwrite` で戻します |
| `mysql 実行失敗: Access denied` | MySQL管理者のパスワードが違います |
| `restore.ps1 を読み込めません（スクリプトの実行が無効）` | `powershell -ExecutionPolicy Bypass -File .\restore.ps1 ...` の形で実行する |
| 日本語が文字化けする | `config.ps1` をUTF-8（BOM付き）で保存し直す |

**NAS自体が壊れたとき**：`C:\backup\work\latest\` に、前回のDBダンプ（MySQL・SQLite）が残っています。サーバーのディスクが無事なら、ここから戻せます（コマンドプロンプトで `mysql -u root -p -e "CREATE DATABASE <DB名>"` の後、`mysql -u root -p <DB名> < C:\backup\work\latest\mysql\<DB名>.sql`。PowerShellでは `<` が使えないので cmd で実行します）。スナップショットや外付けHDDに保管したものがあれば、それも使えます。

復元した後は、日時・原因・戻した世代・確認した内容を記録してください（院内のインシデント報告の様式に沿って）。
